DNX STORE 8.9-opt.13 — ИСПРАВЛЕНИЕ ЗАПУСКА НА RENDER

ЧТО БЫЛО СЛОМАНО

Render успешно собирал проект, запускал команду `python main.py`, но не успевал
обнаружить открытый HTTP-порт. Причина: приложение сначала ожидало подключение
к Neon, выполнение инициализации базы и подключение Telegram, и только потом
открывало порт. При медленном холодном запуске Render завершал процесс со
статусом 1 и показывал `No open ports detected`.

ЧТО ИСПРАВЛЕНО

1. HTTP-порт открывается сразу после запуска процесса.
2. Neon подключается после открытия порта.
3. При временной недоступности Neon приложение не завершается, а повторяет
   подключение через 2, 4, 8, 16 и затем каждые 30 секунд.
4. Ошибка подключения теперь полностью печатается в Logs, поэтому её можно
   точно диагностировать.
5. Если Telegram polling временно оборвался, веб-сервис не падает и повторяет
   подключение.
6. `/health` сразу отвечает HTTP 200 и показывает текущую фазу запуска.
7. Игровая логика, расчёты, каталог, кейсы и NFT-анимации этим исправлением
   не изменялись.

КАК УСТАНОВИТЬ ЧЕРЕЗ GITHUB

1. Откройте репозиторий проекта на GitHub.
2. Нажмите `Add file` → `Upload files`.
3. Перетащите ВСЕ файлы из папки этой версии. Файл `main.py` обязательно
   должен находиться в корне репозитория рядом с `requirements.txt`.
4. Внизу страницы нажмите `Commit changes`.
5. Не добавляйте токены, пароль Neon и другие секреты в файлы или GitHub.

КАК ПЕРЕЗАПУСТИТЬ RENDER

1. Откройте dashboard.render.com.
2. Откройте сервис `dnx-shop`.
3. Откройте `Settings`.
4. Проверьте поле `Start Command`: должно быть ровно `python main.py`.
5. Вернитесь в `Deploys`.
6. Нажмите `Manual Deploy` → `Clear build cache & deploy`.
7. Дождитесь строки в Logs:
   `HTTP server listening on 0.0.0.0:<порт> (release 8.9-opt.13)`
8. После успешного подключения базы появится:
   `Backend initialization complete`

ПРОВЕРКА

Откройте в браузере:
https://dnx-shop.onrender.com/health

Во время подключения Neon допустим ответ:
{"status":"starting","ready":false,...,"release":"8.9-opt.13"}

После полной готовности должен быть ответ:
{"status":"ok","ready":true,"database":"ok",...,"release":"8.9-opt.13"}

Если статус долго остаётся `starting`, откройте Render → Logs. Теперь там будет
полная конкретная ошибка Neon/схемы, а сам процесс не будет завершён из-за
отсутствия порта.

ENVIRONMENT

В Render → Environment должны остаться заданными как минимум:
- BOT_TOKEN
- ADMIN_ID
- DATABASE_URL (рекомендуется одна полная строка Neon)
- WEBAPP_URL
- CORS_ORIGIN

Значения секретов не копируйте в инструкцию и не публикуйте в GitHub.

DNX STORE — УСТАНОВКА V8.9-OPT.22
=================================

ЧТО ИСПРАВЛЕНО В ЭТОЙ СБОРКЕ
----------------------------
1. Каталог, корзина, профиль/инвентарь и кейсы больше не запускают постоянные NFT-анимации.
2. Во всех списках и в рулетке кейса показывается стабильный нулевой кадр NFT.
3. Анимация запускается ровно один раз только при каждом открытии окна характеристик NFT, затем останавливается на нулевом кадре.
4. Нулевые кадры создаются с прозрачным фоном и единым масштабом модели 70/30, поэтому не должно быть вложенных фиолетовых квадратов и размытого старого изображения.
5. Корзина, профиль и кейсы ждут подготовку нулевых кадров до финальной отрисовки, чтобы старые и новые превью не смешивались.
6. Версии frontend/backend и ключ кэша обновлены до 8.9-opt.22.
7. Игра и рабочая логика каталога не изменялись.

ВАЖНО ПЕРЕД ЗАГРУЗКОЙ
---------------------
- Не переносите старые index.html, main.py, tgsticker.js или tgsticker-worker.js поверх этой сборки.
- Не меняйте существующие секреты Render. Все пароли и токены должны оставаться только в Render → Environment.
- Версия Python оставлена прежней: 3.12.8 (файл .python-version).

КАК ЗАГРУЗИТЬ ФАЙЛЫ В GITHUB
----------------------------
1. Распакуйте архив dnx-store-stars-final-v8.9-opt.22.zip.
2. Откройте https://github.com/denixl-11/dnx-store и войдите в свой аккаунт.
3. Откройте основную ветку проекта.
4. Нажмите Add file → Upload files.
5. Откройте распакованную папку dnx-store-stars-final-v8.9-optimized.
6. Выделите ВСЕ файлы внутри этой папки и перетащите их в окно GitHub.
   Важно: загружайте содержимое папки, а не саму внешнюю папку целиком.
7. Дождитесь окончания загрузки.
8. В поле сообщения напишите: Release 8.9-opt.22
9. Нажмите Commit changes.

КАК РАЗВЕРНУТЬ НА RENDER
------------------------
1. Откройте https://dashboard.render.com.
2. Выберите ваш Web Service dnx-shop.
3. Откройте Settings.
4. Проверьте Build Command:
   pip install -r requirements.txt
5. Проверьте Start Command:
   python main.py
6. Проверьте, что Root Directory пустой, если файлы лежат в корне GitHub-репозитория.
7. Откройте Environment и убедитесь, что старые переменные присутствуют. Не удаляйте и не публикуйте их.
8. Перейдите в Manual Deploy.
9. Выберите Clear build cache & deploy. Это обязательно: иначе Telegram/Render могут смешать старый JavaScript с новым backend.
10. Дождитесь статуса Live.
11. В Logs должна появиться строка запуска приложения без Traceback и без сообщения No open ports detected.

ЧТО СДЕЛАТЬ В TELEGRAM ПОСЛЕ DEPLOY
-----------------------------------
1. Полностью закройте мини-приложение крестиком.
2. Закройте чат с ботом и откройте его снова.
3. Запустите мини-приложение заново.
4. Если Telegram показывает старую версию, повторно закройте приложение и подождите 20–30 секунд: версия ресурсов изменена, после этого старый кэш должен уйти.

ОБЯЗАТЕЛЬНАЯ ПРОВЕРКА
---------------------
1. Каталог: карточки показывают нулевой кадр; постоянной анимации нет.
2. Корзина: вместо фиолетового размытого квадрата виден нулевой кадр правильного NFT.
3. Профиль → Инвентарь: все NFT отображаются нулевыми кадрами; кнопки и логика остаются прежними.
4. Кейсы → содержимое: все NFT на одинаковом фоне #242424, без двойного квадрата.
5. Кейсы → рулетка: используются подготовленные нулевые кадры, а кнопка открытия недоступна до их подготовки.
6. Окно характеристик: при каждом новом открытии анимация проигрывается один раз и останавливается.
7. Проверьте iPhone/Android и компьютер: горизонтальной прокрутки и выхода элементов за экран быть не должно.

ЕСЛИ ВИДНА СТАРАЯ ФИОЛЕТОВАЯ КАРТИНКА
------------------------------------
1. Убедитесь, что deploy сделан через Clear build cache & deploy.
2. Убедитесь, что в Render развернут commit Release 8.9-opt.22.
3. Полностью закройте Telegram и запустите снова.
4. Не возвращайте старые tgsticker.js, tgsticker-worker.js и index.html.
